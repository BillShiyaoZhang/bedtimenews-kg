# 报道中的行动与变化

本体 2.4.0、规则 4.2.0 和编译器 1.1.0 增加独立的行动评估。现有 `events[]` 仍逐条对应 processed news；13 个旧领域类型、实体 ID、主题直接分配和新闻日期关系不因为行动分类而改名或合并。

## 可用范围

首批只启用三个已有具体类及其抽象父类：

- `action-legal`：有法院语境的裁判、宣判、判刑，以及有检察院语境的起诉、批捕
- `action-engineering`：有工程、项目或设施语境的开工、建成、通车、投产等描述
- `change-quantitative`：有指标语境，明确同比或环比方向及非零数值的变化描述

其他行动叶类保留 draft，不从旧领域类型机械推断行动。稳定数值、同比持平、一般评论、报道动词和未支持的事件类型不会为了覆盖率而获得行动标签。

## 三态及限定

每条新闻的 `actionAssessment` 必须显式包含 `status`、`reasonCode`、`assignments` 和 `review`：

- `applicable`：至少一条满足当前规则的报道描述；包括明确计划、预测、条件或否定描述，不能读作「已发生」
- `undetermined`：当前规则没有充分支持，或范围、限定存在歧义；默认落在这里
- `not_applicable`：仅来自对特定 news ID、精确片段 SHA-256 和可见原文区间的明确人工审查；规则未命中不能自动生成这个状态

每个分配有 `conceptId`、`polarity`、`modality` 和独立 `evidence`。极性与模态分开记录。例如明确否定的未来计划仍保留两类原文限定。同一篇的不同谓词分别确定限定范围，不把一处「预计」扩散到整篇。非默认限定必须在每条证据中有匹配的明确词语。`reported` 只表示该局部范围没有命中限定词，不能证明来源可信或现实发生。

问题、比喻、传闻、不清楚的否定附着和脱离条件的后件保守留为未确定。规则不是通用语义理解；漏检是允许的，错误肯定不能以提高覆盖率为理由接受。

## 单一蓝图和精确证据

`data/ontology-source.json` 定义稳定类 ID、状态、层级及显示词表；`data/extraction-patterns.json` 的 `actionExtraction` 定义引用这些 ID 的四条字面规则、限定词和逐新闻人工审查。编译后的 ontology/rules 仍禁止手改。编译器拒绝未知字段、悬空或 draft 目标、重复 ID、不支持的规则模板、错误词表、无效审查锚点及版本。

运行时只消费该新闻自己的已校验片段，不借标题、摘要、相邻新闻或整页文本。`visible-fragment-v1` 用空格遮蔽 Markdown/HTML 元数据、标题、链接地址、图片说明、代码、注释和书名等不作为陈述证据的内容；保留换行及 UTF-16 长度。`predicate`、`scope` 和 `qualifiers` 的 start/end 是这个版本化可见片段的 UTF-16 坐标，与原片段位置一致，不能当作 UTF-8 字节位置。

完整来源页与新闻片段分别验证 SHA-256。结构校验检查精确长度、局部包含、重叠区间文本一致和限定一致；来源校验重新执行同一固定规则，拒绝省略、多加、借用、改写或伪造的证据。仅渲染页面不能替代来源回放。

人工 `reviewedAssessments` 条目包含 `id`、`newsId`、`fragmentHash`、`status: "not_applicable"`、UTC `reviewedAt`、明确 `reason` 和 `evidence: {start,end,text}`。该新闻片段变化时必须重新审查；若规则已获得支持证据，与不适用审查冲突会失败。没有人工审查的真实语料默认不会出现不适用结论。

## 支持记录和维护

审计账本增加可选 `actionAssessments` 表，依赖精确 news revision 和规范化输入哈希。局部谓词、范围与限定使用独立的 exact occurrence witness；重复的同一个词在不同位置不折叠成「第一次出现」。只保留所需局部文本及引用，不重复保存完整新闻文本。

- `action_applicability` 断言记录本条抽取评估状态
- `assigned_reported_action` 断言记录本条新闻中的类、极性和模态组合
- 每处规则证据保留独立支持；同类同限定的多个证据可以支持同一新闻内的分配
- 不同新闻始终有各自断言与支持，不合并成跨新闻事实，不宣称转述或重复来源相互独立

限定发生修正时，旧组合的支持撤回、断言进入 dormant，新组合建立支持。来源撤回只撤回相关抽取支持，其他新闻的支持保持；精确来源恢复可重新激活原 ID。生命周期保留最近活动版本的作用域历史引用，来源消失不等于事实被证伪。

`diff.actions` 单独报告三态、直接类、限定组合、逐新闻变更和确定性摘要。历史缺少评估记作 `unrecordedLegacyNews`，不会伪装成过去已判定不适用。上级筛选是派生查询解释，统计唯一 news ID；同一新闻命中两个下级不会在父类重复计数。

## 发布与验证

语义变更采用 [已接受版本流程](accepted-releases.md) 的同一个受审查 code+generated-data PR 和 migration prepare 命令。普通已启用同步遇到规则、生成器或本体语义变化会拒绝，直到固定输入、完整差异和一致数据获批。源获取仍可增量，KG 候选始终全量重新物化，并在原有原子接受、哈希核对、同 epoch 前向回滚流程中验证新证据。旧无行动字段的账本可以按其原版本读取，不会被悄悄回填。KG 文件统一采用已接受候选使用的确定性紧凑 JSON，减少空白体积；配置与审查报告仍保留可读排版，内容差异按稳定 ID 和哈希检查。

首页条件筛选提供行动类（包括显式父类展开）、三态、极性和模态。多个条件必须匹配同一个分配。首页结果详情及实体浏览的新闻检查器显示原文范围、限定词、规则 ID 和坐标；空结果不自动移除用户条件。

测试覆盖元数据泄漏、跨新闻借用、静态数字、计划/否定/预测、同词多次出现、语义迁移、支持修正/撤回/恢复、父类去重、错误结构与自重哈希篡改。真实语料仍需抽样审查；自动结构验证不是分类准确率证明。词法规则仍可能漏检或误判，页面显示的报道陈述不能用作已核实事实。

本阶段最终诊断样本按 news ID 排序，在每类 affirmative/reported 分配中取 `floor(i × (N − 1) / 3)`（i = 0…3），共 12 条，读取各自完整且验签的新闻片段。样本发现「有法院判决显示」是文书引用、「工厂没法开工」是否定能力；两处已增加排除与回归测试，最终重放保留其余 10 条受支持分配。此非随机、小规模、用于修正规则的诊断不提供准确率估计。

- 司法：`news-00648211ab76`、`news-5a1e0639cd48`、`news-a88a61f06715`、`news-ff3feca6b0af`
- 工程：`news-02a3facc5e16`、`news-673d30cb3789`、`news-b3b194ec23d1`、`news-fff11a0a83ce`
- 数量变化：`news-019474a32443`、`news-53637da68c64`、`news-b8739857fea4`、`news-ffce5d0d9f61`

## 明确未实现

没有单独的报道形式分类（访谈、评论、分析等），也没有去重的现实事件 ID、跨新闻事实融合、自动因果、行动主体/客体角色抽取、数值 Observation 事实建模或现实发生时间推断。旧 event.type 仍是领域分类，不能代替报道形式分类。实体身份仍只支持已审查的新闻级分配，尚无同新闻内 mention-span 多身份拆分。新闻边界 split/merge 映射和跨代码 epoch 回滚继续失败关闭；局部依赖重算只可作为以后经全量等价测试验证的优化。
