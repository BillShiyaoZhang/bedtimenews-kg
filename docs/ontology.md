# 本体设计

本体的目标不是穷尽世界，而是让跨期新闻能够稳定地连接、检索和审查。

## 分层

### 实体类型

- `person`：人物；
- `organization`：政府机构、企业、国际组织；
- `place`：国家、地区、城市；
- `infrastructure`：铁路、桥梁、管网等物质系统；
- `policy`：规划、监管与公共政策工具；
- `industry`：产业部门、技术路线与供应链；
- `concept`：用于跨时期连接报道的议题与分析概念。

### 事件类型

事件类型回答“发生了什么性质的变化”，包括历史节点、基建进展、政策变化、市场变化、技术进展与公共讨论。

### 关系类型

关系分两类：

1. 时间与过程关系：`precedes`、`continues`；
2. 解释关系：`enables`、`responds_to`、`contrasts_with`。

解释关系比共同出现更强，必须保留证据。不要把“先后发生”自动提升为“导致”。

## 修改规则

新增类型前先回答：

1. 现有类型为什么不能表达？
2. 新类型的正例与反例是什么？
3. 它能否长期用于多个议题，而不是只服务一个事件？
4. 关系是否有明确方向？
5. 维护者能否根据描述对同一案例得到接近的判断？

发布后的 ID 应保持稳定。显示名称和描述可以演进，重命名不会自动重写历史数据。

## 版本

`ontology.version` 与 `kg.schemaVersion` 应同步。兼容性说明：

- 新增可选类型：小版本；
- 改变关系方向或语义：大版本；
- 仅修正文案：补丁版本。
