# 本体设计

本体回答“独立新闻可以被怎样稳定描述”，抽取规则回答“如何从已经拆分的新闻中复现这些描述”。页面到新闻的边界由 `data/processed/news.json` 和 `data/news-overrides.json` 管理，不属于 ontology。

## 2.3 / 4.1：声明式蓝图与兼容迁移

本体是抽取蓝图，KG 是从已验签新闻生成的版本化结果。当前唯一语义源是
`data/ontology-source.json`；抽取词面规则在 `data/extraction-patterns.json`，
通过稳定概念 ID 引用定义。编译器生成 `data/ontology.json` 和
`data/extraction-rules.json`，保留有语义影响的规则/词序，不使用当前时间。
生成文件只能由编译器写入。

三套层级分别建模：

- 实体类：`subClassOf`；实例的 `instanceOf` 与类继承不同，`partOf` 仍是实例组成关系；
- 事件行动：Occurrence → Action / StateChange；当前定义为草案，尚未给新闻生成行动断言；
- 议题：`broaderTopic`，一级为经济与产业、科学与技术、资源/环境/基础设施、民生/公共服务、治理/法律、国际/安全、教育/文化/体育、风险/公共安全；27 个既有议题保留原 ID、名称和规则。

每个概念都有稳定 `id`、`label`、真正名称 `aliases`、定义、状态、父节点和一个
主导航父节点。额外父节点可形成无环 DAG；闭包由编译器生成。父级检索仅展开查询，
不制造父级实体、新闻关联、证据或关系；按唯一新闻计数，并显示直接/继承命中原因。
普通关键词检索不会自动做层级展开。

`mappings` 是显式兼容注册表：7 个既有实体类型、27 个议题概念及其已发布实体 ID
都保留。主题实例不再从 label 重新计算 ID，改名夹具验证候选、产物和证据引用都
保持身份。其他命名实体的旧哈希身份方式尚未改造。`policy` / `document` 只映射到
宽泛 InformationResource，并保留 legacy type，不能据旧类型猜测细分类。

13 个旧 `event.type` 是报道领域，继续作为兼容分类运行；绝不机械转换为新行动。
当前 `events[]` 仍是每条新闻一对一语义投影，不是跨新闻去重的现实事件。
`precedes` 只表示新闻发布日期的先后，不保证现实事件发生顺序，更不表示因果。
“排班、休息质量、投资拉动、居民部门”仍是已有议题触发证据，不自动变成行动者、
数值观测、健康诊断或因果事实。

### 修改与验证

1. 编辑唯一语义源或抽取模式，审查定义、映射和触发范围，并显式增加相应版本；
2. `npm run ontology:compile`；
3. 在固定上游版本执行 `npm run kg:rebuild`，审查完整数据差异；
4. `npm run ontology:check`、`npm test`、`npm run lint`；
5. 提交源定义、编译结果、KG、状态与报告，一起送审。

编译器拒绝未知/重复 ID、跨类型父节点、孤立/循环、错误 domain/range、漏映射、
非活动议题上的活动抽取规则，以及在规则中重新定义主题名称。构建、更新和源校验
均先检查编译产物是否逐字节新鲜，禁止通过自动生成掩盖手改产物。Node 与浏览器
共享层级结构及闭包验证器。

KG 和 archive state 同时记录编译器版本、蓝图 SHA-256、模式 SHA-256。
即使忘记增加版本，同版本规则改动也会使普通 `kg:update` 拒绝混合已接受数据，
而不是沿用旧来源元数据。显式重建后重复生成必须确定，普通 no-op 更新不改数据。

本次固定源迁移保留全部 9,638 条新闻投影、1,764 个实体、8,141 条时序关系及
2,077 个引用来源的内容；processed news 文件不变，仅升级 schema/rule 与编译指纹。
这些数量是迁移时验收快照，不限制将来合法增加新闻。

### 本 PR 的边界及后续

本阶段完成层级蓝图、编译器、兼容映射、真实的父级检索与失配防护。
完整支持生命周期仍需独立实现 SourceVersion → NewsRevision → EvidenceSpan →
ExtractionRun → AssertionRevision / Support，再生成实体、属性、关系和检索投影。
后续先保留各支持与审计/发布快照，再支持受审查的修改、删除、支持撤回和可逆
merge/split；删除来源不等于事实为假，也不能直接删除仍有有效支持的事实或身份。

当前全局出现门槛、名称重扫、时序上限/相邻关系和日期锚点仍会产生跨新闻依赖。
本阶段没有把 append-only updater 改称全量等价算法；后续约万条规模优先采用完整
候选重算与差异审核，再做原子版本发布/回滚。真正改变新闻内容的来源修订或删除
仍不被支持，已有严格拒绝和 preserve_news 校验继续生效。

## 检索 facet

首页直接使用 ontology 中的 facet：

| Facet | 数据来源 | 含义 |
| --- | --- | --- |
| `event` | 兼容报道领域 | 旧版领域分类；不代表行动类型 |
| `subject` | `person`、`organization` | 谁参与或被报道 |
| `place` | `place` | 事件涉及哪里 |
| `topic` | `topic` | 事件属于哪些长期议题 |
| `named_object` | `facility`、`policy`、`document` | 涉及哪些设施、政策或命名文献 |

Facet 是检索入口，也是事件—实体语义角色的发布投影。Ontology
通过 `eventEntityRoles` 明确主体、地点、主题和命名对象各自允许的实体类型，
并要求每条事件至少关联一个角色实体。角色本身是可选的：一条新闻没有命名政策时，
`named_object` 不适用，而不是覆盖失败。

## 实体类型

- `person`：姓名与职务上下文共同确认的人物；
- `organization`：政府机构、企业、学校、国际组织、政党或社会团体；
- `place`：标准国家、行政区和城市，正式名与常用简称归并；
- `facility`：铁路、桥梁、机场、港口、电站与园区等设施；
- `policy`：明确命名的法律、条例、办法、规划、方案等政策文件；
- `document`：调查报告、研究报告、白皮书、年鉴或标准；
- `topic`：跨时期复用的受控议题，不作为行动者。

主体与设施的模式识别容易产生误报，因此只有在多个事件中复现的候选才会进入 KG；地点优先使用标准地名表；主题只来自受控词表。

## 新闻的事件类型

每条独立新闻保留一个兼容报道领域（旧字段 `event.type`），覆盖政策治理、经济商业、基建交通、科学技术、法律司法、冲突安全、灾害事故、公共卫生、环境能源、教育文化、社会民生和国际关系。分类先使用标题与摘要，未命中时再使用经哈希验证的原文片段补充上下文。确实无法稳定判断时使用 `other` 并进入覆盖报告；正式发布数据要求 `other` 为零。这些旧领域不直接给出行动性质；新行动定义与之分开，后续需独立证据。

## 关系

自动生成器只创建 `precedes`：

- 两条独立新闻共同涉及同一高置信实体；
- 日期不同且顺序可确认；
- 关系保存 `viaEntityId` 与证据文本；
- 它只表示时间先后，绝不表示因果。

`located_in` 与 `part_of` 保留在本体中供未来有明确证据的结构关系使用，但当前生成器不会从共同出现自动推断。

## 版本与迁移

- `ontology.version` 与 `kg.schemaVersion` 必须一致；
- processed news schema、拆分器和人工 override 版本写入 KG 与 archive state；
- `extraction-rules.version` 写入 KG 与 archive state；
- 普通上游新增只允许 append-only；
- 新闻边界、ontology 或规则变化必须通过 `npm run kg:rebuild` 显式迁移；
- 存在未审查的上游修改、删除、改名或重复新增时，重建会拒绝执行。

版本建议：

- 新增兼容类型或规则：小版本；
- 改变既有类型、facet 或关系语义：大版本；
- 只修正文案且不影响输出：补丁版本。

## 覆盖定义

必填语义覆盖以独立新闻为分母，四项都必须达到 100%：

- 至少一个语义实体；
- 一个非 `other` 的具体事件类型；
- 精确一个仍存在且片段哈希一致的来源；
- 至少一个可检索字段。

主体、地点、主题和命名对象不是每条新闻都适用，因此只报告 facet
出现率。将它们强制补到 100% 会制造虚假实体，违背 ontology 语义。

## 名称、抽取触发词与新闻证据（2.2 / 4.0 迁移）

下列字段在编译后的 `data/extraction-rules.json` 汇合；名称在 ontology-source 的概念中维护，触发词在 extraction-patterns 中维护：

- `label`：主题的规范名称；
- `aliases`：经审查、可代替规范名称的真正同义名称。默认 `[]`，不能为了覆盖率把相关词塞进来；
- `extractionTriggers`：保留原有匹配行为的抽取信号。命中意味着可关联该主题，不意味着该词是主题的同义词。

例如“工资”和“排班”都可触发“就业与劳动”，但两者不是彼此的同义词。
只提到“工资”的新闻，不能因为同属劳动主题就命中“排班”查询。
别名不会自动成为抽取规则；需要改变抽取范围时，单独审查 `extractionTriggers`。
事件分类的 `eventClassification[].keywords` 仍是分类评分词，不是实体别名。

生成器继续用新闻标题、摘要及其已验签片段抽取主题和事件类别，以保持已接受的
关联。另从该新闻自己的片段生成 `event.topicEvidence: [{ entityId, terms }]`；
`terms` 只保存实际出现的触发词，顺序跟随配置，HTML 注释不能提供证据。
证据通过 `event.newsId` 指向 processed news 的精确范围和 SHA-256；全局
`source.extractionVersion` 标识匹配规则版本。不重复保存全文或整页共享证据。
标题/摘要单独触发的主题关联可以没有片段证据条目；标题/摘要本身仍可检索。

搜索收录主题规范名称、真正别名，以及该条新闻自己的实际命中词。
因此正文中的触发词仍能召回新闻，但不再扩展为所有同主题新闻。
这不是新的“全文精确匹配”模式：既有名称归一化、经审查缩写扩展、类型标签、
描述与来源元数据检索保持原有行为，层级检索与这些独立检索策略留待后续审查。

### 迁移与自动更新

这次迁移将 ontology/KG schema 升为 `2.2.0`，抽取规则升为 `4.0.0`
（配置中的旧 topic `keywords` 被显式拒绝）。所有 27 组触发词保持不变，
真实主题别名保守初始化为空，不改新闻边界、实体 ID、事件类别或既有时序关系。
只通过 `npm run kg:rebuild` 生成发布文件，并一并提交 ontology、规则、KG、
archive state 和生成报告；不要手工修补大 JSON。

日常 Actions 继续运行 `kg:update`，不需要新增工作流、模型调用或凭据：

1. 修改配置时显式增加版本，在固定的上游 submodule 上执行 `kg:rebuild`；
2. `kg:validate` 逐条重新验签并比较全部实际命中词，拒绝缺失/伪造/跨新闻借用
   证据、未知主题引用，以及规则版本和主题别名不一致；
3. 现有 `test:required` 自动收录证据、负例、确定性、增量保留与版本一致性测试；
4. 本次迁移重复重建应字节一致，随后重复 `kg:update` 应没有数据变化；
5. 提交前继续运行覆盖测试、lint 和两套构建，审查迁移差异后才合并。

增量路径仍只追加新新闻，不因新的主题证据去重写旧新闻。非主题实体的跨新闻
出现门槛、时序关系的热门实体上限等全局依赖没有在此改变，因此不能把未来任意
增量结果与全量重建字节相等当作普遍契约。删除/修订来源后的证据撤回、实体合并
拆分、受影响记录重抽取与回滚，属于后续独立的 KG 生命周期设计。
