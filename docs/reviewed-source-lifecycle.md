# 受审查的离线来源生命周期

本阶段在隔离候选中实现来源修订、删除、撤回、精确恢复，以及相应支持和旧身份的
休眠/恢复。所有候选都从完整有效来源重算，并重放其整个历史链。生产 updater、
acceptedFiles、新闻/KG 数据、子模块指针和部署工作流保持原有行为。

## 两个命令

```bash
# 初始快照必须与 acceptedFiles 完全相同；活动配置与原始 Git 对象必须齐全
npm run kg:lifecycle -- --source /path/to/archive --output work/lifecycle/seed

# 先审查并提交来源仓库中的修订，再在隔离候选中应用一份精确审查文件
npm run kg:lifecycle -- --source /path/to/archive \
  --baseline work/lifecycle/seed --source-review /path/to/review.json \
  --output work/lifecycle/revised

# 从原始 Git 对象重放所有祖先和当前候选，不依赖当前工作区仍留着旧正文
npm run kg:lifecycle:validate -- work/lifecycle/revised --source /path/to/archive
```

`--history-root DIR` 默认 `work/lifecycle`。所有关联候选必须是此目录的直接子目录；
它是专用历史库，不应混放旧 C 格式或无关目录。`--generated-at ISO` 可显式固定时间；
默认使用已固定来源 commit 的时间。其他运行时间只作诊断，不进入候选身份。

来源目录必须是可用的真实 Git 工作区根目录。每个可见范围内的 Markdown 都逐字节
匹配固定的 40 位 commit 和 SHA-256；未提交修订、未跟踪文件、符号链接、Git 替换
对象、缺失旧对象不能蒙混过关。读取只使用本地对象，不获取缺失的远端对象或凭据。
历史核验允许当前工作区已经变化，但原始 commit/blob 必须仍在。

根快照必须用本阶段代码重新生成。C 候选只提供比较基线；不会因它的 manifest 哈希
自洽就把旧账本升级为可信历史。来源迁移过程中，本体、规则、拆分器、overrides、
生成器代码、运行环境和 accepted origin 都必须保持相同；其他变化需要单独迁移。

## 审查文件

下面是格式说明，不是对真实来源的审批，也不能直接作为有效审查文件：

```json
{
  "schemaVersion": 1,
  "baselineBundleId": "<64 hex>",
  "baselineInventoryHash": "<canonical observedInventory SHA-256>",
  "currentInventoryHash": "<canonical current physical inventory SHA-256>",
  "reviewedAt": "2026-09-30T10:00:00Z",
  "reason": "本次来源变更的审查理由",
  "decisions": [
    {
      "path": "daily/example.md",
      "operation": "revise",
      "fromHash": "<old SHA-256>",
      "toHash": "<new SHA-256>",
      "reason": "此路径、此修订的审查理由"
    }
  ]
}
```

使用标准 JSON 对象的确定性排序序列化计算清单哈希（见 `canonicalJson`）。审查文件
的原始字节作为 `source-review.json` 和输入哈希保存。哈希绑定保证确定性与完整性，
不是数字签名，也不声称验证了审批人的身份。真实来源审查仍由维护者在变更流程中负责。

- `revise`：当前路径的旧/new 哈希必须不同，且路径原来有效。重新拆分后，新闻 ID
  与顺序必须一对一保持；新增/消失新闻边界或身份迁移拒绝
- `delete`：确切旧哈希已经从当前清单消失。该来源贡献从有效快照移除，保留墓碑
- `retract`：明确撤回该修订，原文字节可以仍在，也可以明确消失。不能同时换成另一
  份内容。其他来源不会被连带撤回
- `restore`：只能在同一路径恢复墓碑记录的精确字节。先恢复，再另做一次受审查的
  active revise；不能通过“撤回期间改写→恢复”绕过身份检查

所有变化必须被完整覆盖，过期哈希、重复/冲突/多余审批、隐式改名、新的复制来源和
范围扩张都拒绝。唯一的普通新增可以加入；已经存在的重复来源不会被当作独立确认，
在原身份下的精确恢复不创造新的来源身份。原来撤回的文件维持撤回，即使后续又被
物理删除。文件不可用但没有明确 review 时，只报告失败，不推断事实为假。

## 实际物化与历史

每个包在 C 的新闻、KG、账本和差异之外，增加：

- `lifecycle.json.gz`：观察到的清单、有效清单、来源状态、当前/休眠身份和本次转换
- `source-review.json`：原始审查文件或根快照的 `null`

当前 provenance 只描述当前有效快照。旧支持、见证、保留门槛和分类决定保留在原来
的不可变包里；历史引用始终为 `{bundleId, recordId}`，并把依赖闭包固定在那个包。
当前包用 `self`，避免 manifest 身份循环。不会把多个快照的 Retention 表直接合并。
即使 support ID 未变，前置保留门槛/见证变了也记录为改变的推导，不算完整保留下来的支持。

实体、新闻与抽取断言的旧 ID 可休眠并按同一 ID 恢复。休眠记录指回最后有效的历史包，
不进入当前 KG。恢复时 `before` 可以指向更早祖先；`oldHash=null` 表示直接父包没有
活动记录，不代表历史记录不可读。账本不复制整份旧全文，也不在每个候选里累加旧账本。

断言仍是 `extraction_assignment`：每篇新闻自己的实体关联、旧领域分类、新闻日期
顺序。删除一篇新闻会使它自己的关联休眠；另一篇新闻可保持某实体活跃，不能替被删除
新闻保住其专属断言。跨来源的相同事实融合、真实事件聚合尚未实现。
身份仍是旧 type/name 哈希或固定 topic ID，不声称完成了真实世界同名消歧。
支持计数也不代表独立来源数或可信度。

整个语料重算是必要的：删除一个直接来源可使 2→1 门槛失败，撤销别处的名称重扫；
删除一条新闻可改变 90/250 上限、相邻时序边；删除日期锚点可改变正文未动的旧新闻日期。
这些派生变化都通过新快照与旧快照比较，而不是只移除“该文章自己的边”。

## 验证、成本与保留

构建和独立 verifier 都从根开始，逐包核验字节/版本、原始 commit 内容、审查计划、
重新拆分、抽取与生命周期状态；不能自重算 manifest 就伪造休眠或活动记录。所有已有
源、片段哈希、主题证据、非空语义实体和 KG 结构验证继续执行。语料真的清空后可得到
空图；不会为满足覆盖率虚构主体、对象或地点。

最终写入前和核验返回前，重新检查完整来源、配置、审批字节、所有祖先文件和历史
Git 对象。中途失去任何必需历史记录即拒绝；完整候选只有在暂存读回通过后原子出现。
这只对离线目录原子，不是生产多文件 accepted release。

每个 gzip provenance / lifecycle 各不超过 64 MiB，整包仍不超过 128 MiB。
所有包和账本都在忽略跟踪目录中，不进入 Git、PR 附件或前端。不要自动清理祖先：
每个直接或间接引用的历史包和原始 Git 对象必须保留。被引用对象一旦丢失，核验失败，
不能拿当前文本替代旧版本。这个本地保留契约不是备份或永久归档保证。

完整 9,638 新闻根快照的实测：2,107 个源文件、1,764 实体、108,723 抽取断言、
166,637 支持；新闻与 KG 相对 accepted 数据的增加/移除/改变均为零。根包
74,480,884 字节，其中 lifecycle 原始 JSON 33,114,756 字节、gzip 5,268,307
字节，provenance gzip 43,414,491 字节。包含独立重放和暂存读回约 160.3 秒，峰值
RSS 2.55 GiB，未提高 Node 默认堆上限。第二代无来源变化的候选（含一代祖先重放）
约 291.0 秒、峰值 RSS 2.81 GiB、74,481,228 字节；其 news/KG/provenance 产物与
根包逐字节相同。独立核验两代历史约 246.9 秒、峰值 RSS 2.92 GiB，均未提高堆上限。
新增的历史状态不进入前端产物。生产集成必须另设经过验证的接受
检查点来控制累积重放成本，不能靠跳过离线历史核验来宣称已支持无限历史。

历史长度为 n 时核验会重放 n 个快照，存储也随完整快照增长；当前实现优先完整性，
尚无增量历史压缩。命令输出 runtime、峰值 RSS、包大小和重放祖先数；不能把这些
诊断时间写回 bundle 内容。生产接受前还必须确定持久审计存储、备份、保留责任和预算。

## 仍需实现

- 生产级全版本 manifest、accepted 数据/索引/来源的原子接受、发布指针与回滚
- 审计库的持久存储与保留策略，以及安全的历史格式/代码迁移
- 新闻边界拆分/合并、来源改名和路径复用的显式身份迁移
- occurrence-level mention 指派、可逆实体 merge/split、真实世界消歧
- 跨新闻事实身份、真正的行动/状态变化抽取和现实事件聚合
- 在等价性证明后才实施局部依赖重算

本 PR 不自动写入任何真实来源审查，不启动生产同步，也不允许普通 updater 接受此前
拒绝的来源内容修改/删除。后续集成仍需单独审查和合并批准。
